# 变更日志

## v2.1.0

### ✨ 新增：附件同步

思源里插入的图片 / 音频 / 视频（`assets/` 下的文件）现在会跟着块一起同步。

**为什么需要**：之前只同步块内容，块里的 `<img src="assets/xxx.png">` 引用传过去了，
但图片文件没传，另一台设备打开就是裂图。

**怎么做的**：

- 从块 DOM 里正则扫出 `assets/...` 引用（覆盖 `src=`、`![]( )`、`url( )`、`data-src=`）
- 推块**之前**先调 `/api/asset/check` 问服务端缺哪些 → 只传缺的（省流量）
- 收到远端块并写回本地后，检查本地缺哪些 → 只下缺的
- 服务端新增 `asset_added` WebSocket 事件，其他设备能立刻来拉新附件
- 附件用「路径」做键（不用块 ID），文件本体存 `<数据目录>/files/<path>`，数据库只存元信息

**新增接口**：`/api/asset/{check,upload,download,list,delete}`，
后台新增「附件」页（缩略图预览 / 筛选 / 大小统计 / 下载 / 删除），看板加了附件统计卡片。

**配置项**：插件设置 → 同步页签新增「附件同步」开关和「单个附件大小上限（MB，默认 50）」，
以及「全量上传附件」按钮（服务端空库时用）。

**设计取舍**：

- 附件**只增不删** —— 块删了附件仍保留在服务端，避免误删用户素材；要清理由后台手动删
- 服务端删除附件后，**不远程删各设备本地的文件**（只记一条日志）
- 超过大小上限的附件跳过并记日志，不会静默丢弃
- 单附件服务端上限 200MB

### 🔧 其它

- 服务端版本 2.1.0；`MinPluginVersion` 仍是 2.0.0（2.0.0 的插件照常能用，只是没有附件同步）
- 老库自动加 `assets` 表，无需手动迁移

## v2.0.0

服务端与插件整体重写。这一版把 v1 里**会导致同步完全不可用**的几个 bug 全修了，
并把管理后台从「一个表格页」做成完整的管理界面。

### 🐞 修复（v1 的致命问题）

1. **服务端没有 CORS 响应头**
   插件跑在思源前端（Docker 网页端是 `http://host:33666`，iOS 是 `http://127.0.0.1:6806`），
   与同步服务不同源。带 `X-Device-Key` 的请求会先发 `OPTIONS` 预检，
   没有 CORS 头浏览器直接 `Failed to fetch`。
   **现象极具误导性**：WebSocket 不受影响，所以插件显示「已连接」，
   但注册/推送/拉取全部失败，很容易被误判成网络问题。
   → 现在所有响应都回显 Origin 并处理预检。

2. **`delete` 操作的 `op.data` 是对象**
   思源事务里 `delete` 的 `data` 是 `{"createEmptyParagraph":false}`，
   v1 直接当字符串塞进 `markdown` 发出去，服务端 `json.Unmarshal` 失败 →
   `400 请求格式错误` → 推送永远失败。
   → 现在只接受字符串类型的 `data`。

3. **写回远端用错了 `dataType`**
   v1 用 `dataType: "markdown"` 调 `updateBlock` / `insertBlock`，
   但上报上来的是**块 DOM**：HTML 会被当纯文本写进去，而且新块会生成新 ID——
   同步是按块 ID 对账的，丢了 ID 后面全对不上。
   → 改成 `dataType: "dom"`（内核原生支持，且保留 node id）。

4. **注册成功后设备密钥没有落盘**
   v1 只把密钥填进输入框，要用户再点一次「保存配置」才写入存储。
   中间任何一步没做，密钥就丢了 → 点同步报「请先配置服务器与设备密钥」，
   而服务端日志显示设备其实注册成功了。
   → 现在注册成功立即写入配置并落盘。

5. **增量游标 `lastRev` 没有持久化**
   v1 每次加载都从 0 开始，导致**每次打开思源都会把其他设备的历史变更全部重放一遍**。
   → 现在持久化在插件存储的 `lastRev`，重连只补断线期间的变更。

6. **待推送队列没有持久化**
   v1 重启/切后台丢队列。→ 现在存在 `pending`，重启后继续推。

7. **服务端建索引早于补列**（v1 → v2 升级时才会暴露）
   老库没有 `notebook_id` 列，先建索引会直接 `no such column` 起不来。
   → 索引放到迁移之后建。

8. **v1 库列名迁移**
   v1 内容列叫 `markdown`，v2 叫 `content`。→ 启动时自动改名搬数据。

### ✨ 新增

**服务端**
- 管理后台整体重写：侧边栏 + 看板 + 深浅色主题 + 响应式，纯手写 CSS 无构建依赖
- 设备管理：查看密钥 / 改名 / 备注 / 重置密钥 / 删除
- 变更日志：分页 + 按设备/操作/关键字筛选，点块 ID 直接看历史版本
- 笔记本 → 文档 → 块 三层浏览（插件上报目录结构）
- 分享链接：公开只读页，支持密码、有效期、访问计数
- 服务端设置：站点名 / 是否允许注册 / 是否允许分享 / 自动快照保留数
- 后台实时通道（WebSocket）：设备上下线、新变更、新冲突即时刷新
- JSON 备份导出
- `/api/hello` 握手、版本与协议校验
- 请求日志中间件（API 调用可追溯）
- 按设备统计变更数/块数

**插件**
- 设置面板重做：连接 / 同步 / 设备 / 日志 / 关于 五个页签，实时状态徽章
- 「测试连接」按钮：不需要密钥就能验证网络与服务可达
- 「全量上传本机内容」：服务端空库时把本机每篇文档整体推上去（文档为单位，一篇一次请求）
- 「首次全量同步」：把服务端全部块拉回本机
- 自动同步开关 / 暂停 / 防抖延迟可调
- 排除指定笔记本不同步
- 运行日志（最近 200 条）+ 一键「复制诊断信息」
- 回收站与块历史面板
- 错误信息翻译：`Failed to fetch` 会展开成「连不上服务端（地址）…常见原因：…」
- fetch 加超时，避免移动端「点了没反应」的假死
- WebSocket 心跳（25 秒），防止反代/移动网络掐空闲连接
- 元数据上报（笔记本/文档列表）
- 补齐 docId / notebookId（思源的 update 事务不带 parentID，按块 ID 反查一次）

### 🔧 协议

- 内容字段从 `markdown` 改名 `content`；服务端**两个名字都接受**，老插件不会因为改名而同步不了
- 新增 `notebookId`、`force` 字段
- 协议版本 `2`，插件与服务端会互相校验

### 📌 已知边界

- **不 `force` 时**：父块还没同步过来的插入会被跳过，需要一次全量同步兜底
- **全量上传按文档推送**：接收端如果没有那篇文档（文档 ID 不同），该文档内容会写不进去
- 附件（图片等）不参与同步，只同步块内容
